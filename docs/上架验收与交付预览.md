# 上架验收与交付预览

## 使用方式

发布前打开「发布总览」，在商品内容旁核对「付款后买家收到的内容」。批量商品审核台和同步发布的新建账号审核也展示同一交付区，切换商品后随当前商品更新。

固定文字卡券、专属网盘交付可查看完整正文；长内容单独滚动。批量卡密只说明从库存分配，API 卡券只说明按现有配置取货，图片卡券只说明按配置发送图片。预览不取货、不消耗卡密、不发送消息。私有交付区仅返回给当前所属用户；售前详情中出现相同交付链接时会提示核对是否公开。

发布成功后打开「发布进度」，选择账号，在详情下方查看「上架验收」。新发布商品会自动验收；历史商品可点「重新验收」，也可以在对应商品的对话中说「上架验收」「验收当前商品」或「核对上架内容」。页面对等待中、验收中的记录每 5 秒读取一次保存报告。

有差异和部分待核对的验收报告同时进入「运营待办」，支持按账号、批次、类型筛选并直接打开报告。对话「查看上架差异」「查看验收待核对」可定位对应商品。重新验收期间保留上次未完成的核对，一致后更新待办；托管未完成的同一商品优先显示托管问题，不重复计数。

## 从报告处理回复与发货

在「运营待办 → 查看验收报告」或「发布进度 → 选择账号 → 上架验收」中，先完成原发布账号与商品 ID 核对，再点击「配置 AI 回复」或「检查发货卡券」。两个入口始终读取报告对应商品，背景中打开的其他运营对话不影响处理目标。

「配置 AI 回复」支持复用已有接口，或新增接口并拉取模型。面板展示当前和确认后的模型、账号回复开关，以及将关联的商品知识；核对后勾选确认并应用。应用更新此商品知识及原发布账号的模型与回复开关，账号级配置也会影响该账号其他商品；原自定义提示与发货设置保留。配置读取失败、接口草稿未保存或确认内容过期时，先重新读取并确认；重复提交使用同一保存结果。

「检查发货卡券」支持选择已有卡券或新建文字卡券。先保存选择，检查完整发货内容，再勾选确认并点击「确认替换发货卡券」。保存选择只保留待用卡券；最终确认才更新该商品绑定并启用账号自动确认发货。当前绑定正确但卡券或账号发货开关未开启时，也提供确认入口。账号禁止发货范围继续生效，面板会提示核对；批量卡密与 API 卡券仍隐藏具体库存和凭据。

完成后自动返回原报告，再点「重新验收」核对最新结果；账号、筛选与待办页码保留。未保存内容离开前可选择继续编辑或放弃。回复与发货全部满足当前审核要求后，移除「托管待完善」状态；仍有缺项继续保留待办。商品上架结果、线上标题、售价和其他商品卡券绑定保留，处理配置不会重新上架。

## 账号检查与条件发货规则

验收报告中点击「账号检查」，或在已上架商品的对话里说「检查当前商品账号」「查看发货规则」，即可检查原发布账号。面板核对本地启用状态、是否保存登录凭据、AI 接口与回复开关、此商品卡券及自动确认发货开关。这里不向平台验证登录；实际连接和登录有效性可在「打开此账号管理」中核对，链接自动带入账号筛选，原报告保留在原标签页。

发货限制按规则逐条展示：是否启用、当前商品是否已排除、命中时是否主动关单、关单后是否仅发卡券。启用条件规则表示满足订单条件时拦截，不代表此商品所有订单都受阻。旧账号兼容标记不再被当成整件商品禁止发货；尚未取得实际规则、规则类型未知或格式异常时保留待核对。

确需为此商品排除某条规则时，先核对唯一可用卡券、交付版本和发货开关，再勾选具体规则、勾选确认并点击「确认仅调整此商品」。只追加当前商品 ID 到所选规则的排除名单；账号开关、规则参数、其他商品排除名单和未选规则保留。未启用或未识别的规则在此处保留原设置。页面会说明所选规则原有的关单行为，调整后其他未排除规则仍按实际订单判断。

保存时重新校验当前用户、原成功发布日志、账号、商品、卡券版本与全部规则，并用同一事务更新；过时确认先重新检查，并发重复确认复用保存结果。最多沿用每条规则 500 件商品的排除范围。完成后返回原报告重新验收，保留筛选；操作不补发历史订单，后续订单由现有发货服务处理。

## 核对范围

| 核对项 | 依据与边界 |
| --- | --- |
| 账号与商品 ID | 当前用户、发布账号、`ops:任务ID` 成功日志与确切商品 ID 对应后，才读取平台详情 |
| 标题、完整详情 | 与审核快照逐字比较，仅统一换行和首尾空白 |
| 实际售价 | 按元使用十进制数值比较 |
| 图片／视频 | 比较数量；上传后的链接变化不判为内容差异，不据此确认素材内容或封面顺序 |
| AI 回复关联 | 核对商品知识、账号 AI 开关与模型名称，不调用模型或给买家发消息 |
| 自动发货关联 | 核对当前用户的精确商品绑定、唯一卡券、版本、可用状态及账号开关，不取卡或发货 |

当前平台读取复用鱼小铺商品详情接口。普通卖家、账号失效、平台字段缺失及超时都会保留待核对。单项状态为「一致」「有差异」「待核对」「本次跳过」；只有所有请求核对项都有依据且一致时，报告才显示可读取项目一致。

配置关联通过不代表已给某位买家回复或完成某笔订单交付，实际执行情况请查看回复和发货记录。后续主动修改平台内容会产生差异，应结合实际判断。已发布商品确认更换卡券后，以最新确认的卡券设置重新验收；商品标题、详情等仍按原发布内容核对。

## 重试与保存

验收失败或发现差异不改变上架成功状态，也不创建新的发布任务。平台读取最多等待 15 秒；任务以 60 秒租约合并并发请求，进程中断后可接续。写入时重新校验任务内容及租约，忽略过时结果，并合并保留原商品、草稿与托管记录。

浏览器读取失败时保留已有报告，支持单独重新读取。重新验收期间防重复点击，切换账号后忽略上个账号迟到响应。卡密、API 凭据与固定交付全文不写入验收结果或简短对话事件。

接口均使用当前登录用户的任务归属校验：

- `GET /api/v1/operations/jobs/{id}/publication/audit`：返回保存报告，不访问平台。
- `POST /api/v1/operations/jobs/{id}/publication/audit`：只读验收，不上架、不改价、不发消息。
- `GET /api/v1/operations/jobs/{id}/publication/reply?ai_config_ref=…`：核对原成功发布记录，返回回复变更预览及版本指纹，不返回接口密钥。
- `POST /api/v1/operations/jobs/{id}/publication/reply`：提交配置引用、指纹和 `confirmed=true`，重新核对后在同一事务内应用；相同确认单重复提交复用保存结果。
- `GET /api/v1/operations/jobs/{id}/publication/account`：返回原发布账号的本地状态与逐项规则，不返回登录凭据、模型密钥、规则参数或私有交付内容。
- `POST /api/v1/operations/jobs/{id}/publication/account/rules`：提交所选规则编码、版本指纹与 `confirmed=true`，仅为此商品排除所选规则，不改变规则开关及其他商品。

## 本轮验证

后端回归覆盖文本与金额规范化、媒体数量、字段缺失、精确归属、配置变化、API／卡密预览保密、超时保留成功记录、并发验收租约、过时结果丢弃与批量预览投影。浏览器模拟验证覆盖报告读取、差异展开、失败重试、双击、轮询、迟到响应隔离、窄屏，以及单品／批量／多账号交付预览。全部平台请求和浏览器 API 使用夹具；未对真实商品执行上架或交付测试。

关联处理回归增加账号隔离、明确确认、旧指纹拦截、接口变化回滚、并发提交幂等、商品知识创建与精确更新、自定义提示保留、发货范围保留及托管状态闭环。界面验证增加跨账号处理后返回、接口新建与拉模型、选卡与新建后的独立换绑确认、未保存保护、读取失败重试及手机深色布局。

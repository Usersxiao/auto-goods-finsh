# 运营待办与准备重试

验收报告中的「配置 AI 回复」「检查发货卡券」可直接处理原商品关联，完成后返回同一报告，再重新验收。原账号、批次、类型筛选和页码保留。回复可复用或新建接口并拉模型；发货先保存选择，再检查并确认换绑。仅全部所需关联完成后移除托管待办，仍有缺项继续显示。详细范围与确认流程见 [上架验收与交付预览](上架验收与交付预览.md)。

运营待办也包含「上架验收有差异」和「上架验收待核对」。标题、详情、售价、媒体数量或回复／发货绑定出现差异时，可直接在待办行点「查看验收报告」，展开审核值和实际值，再按需重新验收。缺少平台字段属于待核对，商品仍保持已上架状态。

同一商品优先显示一类待办：托管未完成先处理托管，完成后若仍有验收问题会继续展示。列表只返回允许展示的字段名与状态，不携带私有交付正文、模型凭据或完整审核值。重验期间保留上次未完成的核对，取得新结果后更新；一致后从验收待办移除。

打开报告再返回，会保留当前账号、批次、类型、页码、选择和列表位置，并读取最新待办。末页已处理完会自动回到有效页码；刷新失败保留原列表与选择，暂停依赖旧结果的处理，支持重新读取。手机端分类统计横向滚动，节省商品列表空间。

对话可直接发送「查看上架差异」「查看验收待核对」「查看托管待办」，打开对应筛选；当前商品也可发送「上架验收」执行只读核对。验收列表与报告不提交上架、不改线上商品、不分配卡密。

商品运营顶部、会话侧栏和发布日历均可打开「运营待办」。这里按当前用户本地运营记录集中汇总异常，不受未来7天等日历窗口限制，过去错过的发布安排也能查到。

## 八类待办

| 类型 | 说明 | 处理入口 |
| --- | --- | --- |
| 准备中断 | 素材、模型或生成步骤未完成，检查点仍保留 | 检查商品，预览重新准备 |
| 发布失败 | 原发布已记录失败，草稿保留 | 先检查商品，再预览重新准备 |
| 条件待补充 | 卡券、分类、售价、素材或账号等缺项 | 商品检查连接相应配置 |
| 错过发布时间 | 明确错过排期，或待审核/待发布商品已超过原计划30分钟 | 带入原日期及所选商品，重新安排时间 |
| 结果待核对 | 原发布请求结果尚未确认，或已有提交记录需核对 | 核对原发布结果，保留防重 |
| 托管待完善 | 商品已经上架，AI回复或自动发货配置未完成 | 重试托管配置，不重新上架 |
| 验收有差异 | 实际商品或回复／发货绑定与审核单存在差异 | 查看验收报告，核实处理后重新验收 |
| 验收待核对 | 商品已上架，部分平台字段或关联记录尚未取得 | 查看待核对项目，按需重新验收 |

可按账号、类型筛选和分页。停用账号的待办仍可查看；从日历进入时沿用该批次，也可清除批次范围。原因是按本地状态及已知错误类型归纳的检查方向，不代表平台已确认根因。页面不会展示接口原始错误正文、交付内容或账号凭据。

## 对话操作

- 「查看运营待办」「打开处理中心」「查看发布异常」：打开同一待办列表。
- 「查看错过的排期」「查看发布失败商品」：直接筛选相应类型。
- 「重新准备当前商品」「重新准备这件商品」：生成当前商品的准备重试单。
- 「重新准备本批次商品」「整批重新准备」：仅纳入当前批次的待办商品，展示每件的处理方式与阻碍。
- 「重新准备任务ID为……的商品」：对话解析为明确任务ID，再生成预览。
- 「确认重新准备」：确认上一份重试单后进入原商品队列，完成后等待审核。
- 错过排期的商品可以说「把这些商品从明天20:00开始，每隔10分钟发布」，先查看改期单，再说「确认调整排期」。缺少明确商品范围时会提示补充。

待办上下文最多给对话50件，超出时标记范围不完整。模型的工具只产生准备重试预览，确认执行使用独立的明确确认指令。

## 重新准备的边界

一次选择1至50件。只支持准备中断、发布失败和发布条件待补充的任务。已有文案时重做草稿与分类准备；尚无文案时从原检查点继续生成。保留研究、图片、视频、事实、文案、售价及账号/AI/卡券选择，清除旧发布批准、旧发布快照与旧对话确认，切回审核模式。

确认后仅进入准备队列。即使原来是自动模式，准备完成后仍等待审核，不会沿用旧批准提交发布。未来排期时间保留；已过期时间、排期索引与商品时间不一致、缺少素材文件夹、账号未登录/停用以及连续任务仍有后续步骤时，先提示相应处理。

结果待核对、正在执行、已上架商品保留原发布流程。重试前还会读取当前用户这件商品的原幂等发布日志；待提交、提交中、未知或成功的原记录会阻止准备重试，失败记录账号与当前账号不同也需先核对。

预览只写30分钟有效的本地重试单，不改商品。确认时锁定所选商品、按固定顺序检查账号，并复核任务内容/设置/状态、原排期及原发布日志。任何一件变化都会回滚全部选择。相同重试单成功重复提交复用结果；每件商品对话都会保留已确认重新准备的记录。

## 界面处理

勾选当前可处理商品，点击「预览重新准备」，逐件核对商品与账号，再勾选确认。混合选择了错过时间的商品时，先使用「重新安排所选时间」，进入日历的新旧时间对比。选择、筛选、分页或刷新会清除过期的页面预览与确认勾选。

结果待核对的行提供「核对原发布结果」，复用原发布结果核对服务；已经成功但托管未完成的行提供「重试托管配置」，复用已有托管服务。两个入口都操作对应任务ID，切换对话不会把动作送给其他商品。

## 接口与存储

- `GET /api/v1/operations/attention`：account_id、batch_id、kind、page、page_size（10/20/50）。
- `POST /api/v1/operations/repair-reviews`：明确job_ids，生成准备预览。
- `POST /api/v1/operations/repair-reviews/{id}/apply`：fingerprint及confirmed=true。
- `POST /api/v1/operations/jobs/{id}/publication/check`：核对原发布请求。

均使用原登录与任务归属检查。重试单保存在 `xy_operation_repair_reviews`，启动自动建表。列表仅提取窄字段；对有大体积研究JSON的任务先物化匹配ID，再按小字段排序分页，避免MySQL排序缓冲区携带完整研究正文。

测试使用隔离用户、本地商品夹具与模拟模型/发布服务，覆盖归属、八类问题、验收与托管去重、重验状态保留、历史错过排期、大研究记录、私有差异值隔离、预览无修改、过期、整批回滚、账号注销、原日志变化、重复确认和准备后保持审核。浏览器模拟覆盖筛选、报告往返、刷新失败、迟到响应、有效分页及手机和深色界面。没有创建真实上架、修改真实订单或发送买家消息。

# AI 议价与订单改价

账号「AI 回复设置」中的优惠比例、最高减价金额同时约束成交报价，任一为 0 时没有自动优惠。
议价轮数指实际让价轮数，普通询价不占轮数。例如标价 100 元、最多优惠 10%、最多减价
100 元、3 轮，报价依次为 96.67、93.34、90 元，第 4 次保持 90 元。

报价保留 24 小时，按用户、账号、买家、商品和会话隔离保存。买家先拍下，等待订单改价
核验成功再付款。待付款事件或买家「已拍下」「改一下价」等消息会尝试兑现已有报价。
开启「已下单用户禁止 AI 回复」时已有报价结算仍可处理；AI 总开关、时间范围及人工暂停仍生效。

## 订单处理

只处理与报价的账号、买家、商品、会话一致的唯一待付款订单，当前版本支持单件无规格商品。
多笔待付款、多规格、多件、身份不匹配、金额含义不明确或平台未开放改价时，提醒卖家核对。
已付款、关闭、退款等状态不提交改价。

按官方网页客户端的接口合约调用：

1. `mtop.idle.web.trade.order.detail` 核对身份、数量和待付款状态。
2. `mtop.taobao.idle.trade.order.modify.price.render` 读取平台下发的改价字段及金额（元）。
3. `mtop.taobao.idle.trade.user.adjust.price` 发送对应字段（分的字符串）及 `orderId`，保留运费。
4. 再读详情和价格，核对成功后才提示刷新订单付款。平台确认前不宣称改价成功。

接口依据：闲鱼官方 `xy-site/0.0.183/js/p_order-detail-index.js`。
最终可用字段、权限及返回结构仍以实际账号的平台响应为准，未知字段交由人工核对。

报价和提交状态存入独立表 `xy_ai_bargain_quotes`，首次使用自动建表。
提交前持久化 `applying`；断线、超时或进程退出后只读对账，不盲目重复改价。
此功能只修改单个订单，商品公开售价和已经付款的金额不受影响。

每次实际提交另存入 `xy_ai_bargain_attempts`：记录报价标识、金额、结果、平台错误码和
已脱敏的原因，不记录 Cookie、聊天正文或买家资料。自动回复日志的「处理提示」显示失败原因。
平台明确返回系统繁忙或服务故障时，等待 3 秒后最多重试一次，每次重新检查订单与金额。
新订单刚建立时，闲鱼可能返回 `FAIL_BIZ_CANNOT_MODIFY_FEE` 并提示「请稍后重试」；
这类明确的临时拒绝等待 5 秒后最多重试一次。相同错误码未包含重试提示时不自动重试。
延迟后重新读取待付款状态、买家与商品、价格表单和当前优惠设置；付款、权限变化、
AI 关闭或人工暂停均会阻止第二次提交。平台价格表单标记为只读时也不提交。
买家也可以发「重试改价」重试已明确失败的报价；相同报价最多 2 次提交。
登录、验证、权限问题交由卖家处理。网络结果未知时仍只读对账，即使收到重试请求也不重复提交。

## 改价后保持 AI 回复

闲鱼会用卖家身份推送「我已修改价格，等待你付款」「你当前宝贝拍下未付款」等订单卡片。
自动回复入口按平台 `MsgCard`、`updateHead`、卡片类型和已知订单提示共同识别此类消息，
记录为「平台订单通知（保持自动回复）」，不触发人工回复暂停。真实人工文本、图片等操作
仍按原来的人工暂停设置处理；原本已经生效的人工暂停也不会被订单卡片解除。

## 开发验证与部署

测试文件 `websocket/tests/test_ai_bargaining.py` 使用隔离账号和真实数据库持久化，所有平台请求
和消息发送均模拟，不触碰真实交易。使用项目原有源码镜像构建会包含新文件；本机的
`compose.local.yaml` 已挂载本次修改，需重建 WebSocket 容器以加载。

```sh
docker compose -f docker-compose.yml -f compose.local.yaml run --rm --no-deps -T \
  --entrypoint python -e PYTHONPATH=/app/websocket:/app \
  -v "$(pwd)/websocket/tests:/app/websocket/tests:ro" websocket \
  -m unittest discover -s /app/websocket/tests -p test_ai_bargaining.py -v
```

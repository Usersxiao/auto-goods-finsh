# 商品版本记录与回退

商品运营页顶部的历史图标打开「商品版本记录」，批量商品审核台也提供「版本对比」入口。

## 日常使用

- 说「保存当前版本『首轮审核通过』」可给当前草稿命名存档，中文引号「」和“”均支持。
- 说「查看商品版本」可查看记录。
- 说「恢复上一版本」或「恢复版本 #123」会先展示对比单；说「确认恢复版本」才执行恢复。
- 页面中可选版本，对比当前商品和选中版本的标题、完整详情、价格、图片顺序、封面与视频，勾选检查确认后恢复。
- 桌面并排对比，手机可切换当前商品与选中版本。

## 自动记录

完成草稿生成、修改文案或售价、切换文案版本、增加视频、调整图片和封面时自动留档。重新读取素材、补充事实、重写文案或应用模板前，保留已有的完整草稿。重复保存管线检查点且商品内容一致时，不增加记录。连续任务也支持在生成后执行「保存当前版本」。

首次部署后的历史记录从后续操作开始积累；已有草稿可以手动保存。界面展示最近100条记录。

## 恢复范围

恢复未发布商品的文案版本、选中方案、售价、图片和视频，同时更新当前素材库草稿。当前发布账号、AI接口、发货卡券、成本规则、研究结果和排期时间保留。恢复前的当前内容也会留档。

恢复后进入「审核后发布」，撤销原发布快照、对话发布确认和定时发布批准；有排期的商品需要重新检查并确认排期。定时任务只有重新审核后才会恢复自动执行。

已发布、正在生成、发布结果待核对的商品，以及尚有连续任务的商品，先处理当前任务再进行本地版本恢复。线上文案修改使用已有「经营优化」审核流程。

恢复时重新检查当前价格边界、成本底线、素材库归属、媒体文件是否存在、素材来源和事实是否一致。旧版价格越过当前底线、历史媒体文件缺失，或换过商品事实/素材文件夹时，会提示重新准备。

## 接口与数据

复用原登录和任务归属校验：

- `GET /api/v1/operations/jobs/{job_id}/revisions`
- `POST /api/v1/operations/jobs/{job_id}/revisions`，`label`、`expected_hash`
- `GET /api/v1/operations/jobs/{job_id}/revisions/{id}`
- `POST /api/v1/operations/jobs/{job_id}/revisions/{id}/restore`，`expected_hash`、`confirmed: true`

`expected_hash`来自当前列表或对比单；过期页面需要重新查看后再提交。

表 `xy_operation_product_revisions` 在服务启动时创建，记录与内容修改在同一事务内提交；失败操作回滚版本写入。快照仅存商品内容、价格和媒体元数据，商品事实来源只存摘要哈希；账号凭证、AI密钥、私有发货文本及完整竞品研究数据均排除。任务删除时版本通过外键级联清理。

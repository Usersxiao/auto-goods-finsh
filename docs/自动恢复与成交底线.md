# 自动恢复与成交底线

## 对话入口

在商品运营中可以直接说：

- `查看异常` / `查看恢复任务`：查看自己各账号的回复、改价和发布异常。
- `核对发布结果`：读取当前商品的原始发布记录，恢复确认成功的商品链接和托管配置。
- `最低成交价设为22元`：设置当前商品的成交下限；已上架商品也支持，保留原商品和发布记录。
- `查看成交底线`：查看最低成交金额与成本是否填齐。

设置默认最低成交价只影响新任务。选择当前商品后设置，才更新该商品后续的自动议价规则。修改线上标价继续沿用原商品编辑流程。

## AI生成恢复

首次调用模型前将任务保存至 `xy_ai_reply_recovery`。模型超时、连接异常、429、5xx和空文本会进入恢复队列，首次失败至少等待5秒，第二次失败至少等待20秒，总计至多3轮生成。单轮模型调用总时限45秒，SDK网络自动重试关闭；OpenAI兼容格式适配与截断输出修复仍在这45秒内进行。

恢复使用账号的当前连接，并重新经过商品归属、账号AI开关、时间范围、买家限制、人工暂停和过滤规则。原用户消息ID保留，恢复生成沿用同一条消息与议价事件ID。恢复不会重复发送买家消息通知。

任务从首次处理起3分钟内有效。新买家消息取消同会话同商品旧任务，包括走关键词回复的新消息。模型返回后和真正发送前再次检查状态；开启人工暂停或关闭AI后，待发送的旧回复被丢弃。配置类4xx直接进入待检查状态，避免反复消耗请求。

发送前先持久化 `sending` 状态；重启后遇到这一状态只标记回执待核对。已经提交给传输层的消息继续用原发送日志确认回执；队列不再次发送。重启时只有尚未发送、仍在有效期内的生成任务可以继续。

消息正文只在本地任务表保存，用于重试；异常概览不包含买家ID、正文、交付私密内容或接口凭据。

## 发布与订单核对

发布结果未知时，后台每10秒检查待核对任务，单任务最多自动核对3次，核对间隔逐步延长。只接受相同登录用户、发布账号和原始 `ops:任务ID` 对应的发布记录。记录携带商品ID但状态未知时，会读取该账号的平台编辑表单，逐项比对标题、详情和金额；原记录未返回商品ID时保留待核对状态。记录明确成功后恢复原商品，继续关联原确认过的回复/发货配置；关联失败保留成功商品，单独检查托管配置。记录明确失败时回到可检查重试状态。

未取得确定结果时保留防重，并在第三次核对后写入对话提醒。这里没有按标题猜商品或重新调用发布接口。可以再次说“核对发布结果”主动读取；原记录一直未知的情况仍需核实闲鱼商品。

订单改价结果未知时，另有至多3次后台延迟读取。该后台只核对订单与金额；结果仍未知时展示在异常概览。明确的暂时性改价拒绝继续使用原有的5秒延迟、最多一次重新提交规则。

## 统一价格规则

发布建议价、发布前检查、买家报价和实际订单改价共用 `common/services/pricing_policy.py`。

最低成交价取“手动设置的最低成交价”和“已填写成本与目标贡献经费率折算后的金额”中的较高值，向上取整至分。未填写成本不作为已验证利润，但已经填入的成本仍计入下限。折扣还受到原账号最大优惠金额、比例与议价轮数限制。

商品运营发布时保存价格规则及任务关联；议价前读取所属用户、账号和商品对应任务的最新规则，已发布的旧任务也适用。报价后提高下限，会拦截旧报价的继续承诺和实际改价。结果未知的请求先核对已提交金额，保留人工或平台已给出的更低价格记录，避免对历史订单反向加价。

## 验证与部署

回归使用隔离账号和模拟的模型、消息发送及平台接口。覆盖恢复时限、重启租约、重复事件、发送前崩溃、后续新消息、账号关闭AI、用户归属、成本取整、旧商品动态底线、确定与未知发布结果。

部署新增 websocket 启动时的恢复任务，operations 启动时的发布核对任务。新表采用独立模型建表；既有订单、消息及发布表结构保持兼容。本地 Compose 与 operations Dockerfile 已包含新增服务模块。

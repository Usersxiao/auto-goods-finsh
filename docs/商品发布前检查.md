# 商品发布前检查

商品运营页顶部检查图标、商品预览中的检查图标，以及批量商品审核台的「商品检查」打开同一份本地检查结果。

在对话中可以说：

- 「检查当前商品」「发布前检查」「商品质检」。
- 「按检查建议优化文案」。
- 检查完整优化前后对比后，说「确认应用优化」。
- 连续准备可以把「最后检查商品」放在整条任务末尾，检查摘要会保存在当前对话。

## 检查内容

- 发布条件：沿用当前发布预检，列出账号、分类、所在地、售价、已启用的AI回复和发货配置等待补充项。
- 文案：标题和详情长度、模板占位文字、商品交付类型是否写清，以及当前私有发货链接或口令是否出现在公开文案中。
- 事实：统计现有事实、检查选中文案引用的事实编号是否存在，统计待核实信息。这项检查核对引用和材料完整度，事实真实性仍由卖家确认。
- 媒体：图片数量及重复项、本地图片和视频是否存在、封面可读性与尺寸建议。远程地址只标记待发布器检查，本地检查不请求远程媒体。
- 定价：试售价标记、成本及目标贡献完整度、预览售价与方案建议价是否一致。
- 托管：AI回复、自动发货的当前开关和配置检查状态；关闭的开关沿用卖家选择。
- 研究：显示当前研究数量，并区分热度数据与实际销量。

「发布待补充」沿用现有发布条件，文案、媒体、价格等建议单独列在「审核建议」中。建议项供卖家核对，不额外修改既有发布规则，也不代表销量预测或平台审核结果。默认只显示待处理项，可切换查看全部检查。

## 根据建议优化

页面「生成文案优化对比」和对话「按检查建议优化文案」调用同一服务。使用选中的文案版本和已有商品事实，生成标题、完整详情的优化审核单；售价、账号、素材与卡券保留。

生成只创建待审核方案。即使商品当前处于自动发布模式，也先审核本次优化。确认后写入草稿，沿用现有版本留档机制；已确认的定时发布因内容变化而需要重新审核。

检查指纹覆盖商品内容、价格边界、当前发布配置、方案序号和本地媒体文件状态。页面过期、素材被替换、生成期间商品被修改时，提示重新检查，过期方案停止应用。

生成后的方案再次检查占位文字与私有交付信息。在检查通过前方案处于内容待检查状态，审核应用入口保持关闭；检查中断可重新生成。当前公开文案已出现私有交付信息时，需要先编辑移除，再生成优化方案。缺少事实、标题、详情、售价或发布账号时也会明确提示先补齐。

## 接口

- `GET /api/v1/operations/jobs/{job_id}/quality?variant_index=0`
- `POST /api/v1/operations/jobs/{job_id}/quality/optimize`

优化提交包含检查结果中的 `fingerprint` 和 `variant_index`，复用现有登录、任务归属与优化审核服务。检查结果只包含检查项、状态、建议和统计；账号凭证、AI密钥、素材正文、私有发货内容及完整研究数据均排除。

# 历史会话恢复与读取重试

商品运营的当前会话按任务 ID 独立读取，侧栏最近 50 个会话用于导航。从商品工作台、发布日历、运营待办或批量审核打开较早商品后，也会读取该商品的完整内容和消息，不再因任务未列入最近会话而一直等待。

刷新页面时优先恢复当前登录用户在当前标签页最后打开的任务。即使任务已经超出最近 50 条，也继续读取原任务；原来停在新对话则保留新对话。当前历史任务临时补入侧栏，显示“历史”标记，可以继续筛选和切换。输入草稿仍按用户和会话分别保存。

会话列表、商品详情与消息记录分别处理读取结果。列表读取失败会在侧栏给出重试入口，已加载的商品继续使用。消息记录刷新失败保留已读内容与输入草稿，允许继续发送，并自动重试读取。商品详情读取失败时保留已读内容和输入，给出“重新读取会话”入口；读取恢复前暂缓发送、修改发布设置和发布操作。

如果任务返回 403 或 404，页面显示商品可能已移除或不属于当前用户，提供重试、新建对话和打开商品工作台入口。页面保留输入，不自动跳到其他商品。此类结果停止自动轮询当前详情，手动重试后可恢复。

切换商品后，旧商品迟到的详情、消息和发布设置响应不会更新新商品的页面。切换登录用户时重建运营工作区，清除上一个用户的页面状态；所有服务端归属检查继续沿用原接口。

本次修改仅涉及前端读取、状态呈现与交互保护。读取失败不会调用暂停、继续、发布、发货或订单写入。测试使用模拟接口覆盖历史商品打开与恢复、列表延迟和失败、消息失败、商品失效与恢复、快速切换、独立草稿、准确发送目标、手机与暗色显示。

# 发布日历与批量改期

商品运营顶部的日历图标打开「发布日历」。排期卡片和批量审核台也有入口；日历中的「批量审核」会回到原审核台。

## 查看安排

日历按北京时间显示，可查看7、14或31天，切换起始日期，并按账号、批次、状态筛选。每日卡片汇总计划商品、已确认待发布和时间过近的数量，商品列表显示所用账号、时间、模式与当前状态。已发布记录按原计划时间归档，实际发布结果仍以商品发布记录为准。仅展示当前登录用户自己的排期；账号停用后仍可查看历史安排。

同一账号同一分钟安排多件商品，或两次排期间隔不足5分钟时提示时间过近。不同账号分别计算，已取消、已发布以及发布结果待核对的记录不参与冲突计数。窗口边缘会多读前后5分钟，避免遗漏跨午夜的相邻排期；筛选批次或状态时，仍保留与其他批次/状态的冲突提示。5分钟是本地安排建议，不是平台频率保证，也不会成为新的发布门槛。一次最多展示1000条，超过时明确提示缩小范围；截断范围内的计数仅代表已加载记录。

## 对话操作

- 「查看发布日历」或「打开发布日历」：显示未来7天安排。
- 「查看时间冲突」：打开需要留意的排期，包括时间过近、错过时间和执行异常。
- 「查看测试店A未来14天的发布日历」：由对话解析账号与范围，调用相同日历接口。
- 「整批排期顺延一天」「本批次提前2小时」：对当前对话最新批次生成新旧时间对比。
- 「这批商品从明天20:00开始，每隔10分钟发布」：从服务端解析的北京时间开始，按原排期先后安排；默认各账号分别错开，也可明确要求所有账号统一间隔。
- 「确认调整排期」或「确认改期」：应用刚才展示的调整单。原批准撤销，之后仍需重新审核发布。

对话明确提供任务ID或批次ID时按对应选择处理；没有清楚指定范围时会提示补充。整批改期包含该批次所有排期，若其中有正在执行或已有发布记录的商品，会展示原因并保留全部时间。在日历勾选可调整商品后可以只改其中一部分。

## 日历中批量调整

1. 勾选1至50件商品；也可选择当前列表中的全部可调整商品。切换日期、账号、批次、状态或刷新时清空旧选择和预览。
2. 选择「整体顺延/提前」，输入数量和分钟/小时/天；或「按间隔错开」，填写开始时间与间隔，并选择各账号分别错开或统一错开。
3. 点击「预览改期」，查看每件商品的旧时间、新时间、账号，以及调整后时间过近的提示。预览只保存本地调整单，商品排期仍保留原值。
4. 检查后勾选确认并提交。整次调整在一个事务内完成，任一选择已变化则全部保留原排期，重新预览后再提交。
5. 调整后的商品统一使用审核模式，清除旧发布批准和旧发布快照，商品文案、价格、图片、视频、账号、AI和卡券选择沿用原配置。定时等待和错过排期的商品回到待审核；生成失败或主动取消的任务保留原状态，先恢复准备再审核。可在同一日历进入批量审核台。

开始时间必须在未来一年内，间隔1至1440分钟。正在排队/执行、连续任务尚有后续步骤、已有提交或待核对发布结果，以及索引时间与任务设置不一致的商品显示具体原因并禁止批量调整。调整单30分钟有效；确认时重新校验所选商品的内容、设置、状态、原排期与目标时段已存在的其他排期。如果在预览后发生变化，会要求重新预览。时间冲突属于建议，其他事务在校验后新增排期仍可能产生新的相邻安排，可刷新日历检查。

## 接口与数据

均复用原登录及用户归属范围：

- `GET /api/v1/operations/publication-calendar`：start、days、account_id、batch_id、state。
- `POST /api/v1/operations/schedule-adjustments`：明确job_ids及shift/spread参数，生成对比单。
- `GET /api/v1/operations/schedule-adjustments/{id}`：查看自己的调整单，不返回内部校验数据。
- `POST /api/v1/operations/schedule-adjustments/{id}/apply`：携带fingerprint及confirmed=true应用。

调整单保存在 `xy_operation_schedule_adjustments`，启动时自动创建。成功重复提交复用结果，不重复修改；各商品会话写入新旧时间与重新审核提示。日历查询只读取标题、账号、时间等摘要，不返回研究正文、卡券内容或账号凭据，也避免排序完整的大体积研究JSON。

测试使用隔离用户与本地夹具，验证归属、北京时间午夜边界、状态筛选、冲突、顺延/错开、审核过期、内容变化、事务回滚、重复提交和对话确认，不发布真实商品、不改真实订单、不发送买家消息。

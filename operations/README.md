# 商品运营助手

会话侧栏支持按发布账号、商品标题和任务状态查找，显示下一步提示，保留当前会话与输入草稿；最近活跃的旧会话会回到列表顶部。详见 [多账号会话导航](../docs/多账号会话导航.md)。

历史商品按任务 ID 独立恢复，超出侧栏最近 50 条也可打开并在刷新后继续。列表、商品与消息读取失败分别提示重试；快速切换保留各自草稿。详见 [历史会话恢复与读取重试](../docs/历史会话恢复与读取重试.md)。

长对话按会话保留阅读位置，切换、刷新后可以接着看。新增助手回复提供计数与定位入口，回到最新可继续跟随，工具状态不会误报。详见 [长对话阅读与新回复导航](../docs/长对话阅读与新回复导航.md)。

支持自动恢复与统一成交底线：对话中说“查看异常”“核对发布结果”“最低成交价设为22元”“查看成交底线”。失败的AI生成限时重试，已提交的消息与未知发布请求保留防重；商品发布和订单议价共用成本下限。详细规则见 [自动恢复与成交底线](../docs/自动恢复与成交底线.md)。

集成于原后台的「商品运营」菜单，使用原有登录、页面布局、请求封装、账号配置及素材库。后台任务模块位于本仓库 `operations/`，通过同一项目的 Compose 启动。覆盖：关键词采集、热度排名、竞品文案研究、读取本地素材、事实提取、定价、三版商品文案、素材库入库和单品发布。

入口：`http://localhost:9000/product-operations`。在原后台登录后可以直接使用。

日常指令示例：

```text
采集“AI口播源码”的Hot100
我的素材在“/Users/yourname/Desktop/商品素材/AI口播”
确认：交付源码；源码中包含教程；通过网盘发货
查看进度
取消
继续
把文案改得更简洁，突出源码、教程和网盘交付
查看卡券
把当前商品绑定到卡券“AI口播源码”
绑定卡券ID 12
新建卡券“课程源码”，发货内容：网盘链接… 提取码…
```

## 对话、预览与发布

主界面为固定高度的对话区，右侧是独立滚动的商品预览。输入框始终位于对话底部；手机点击右上角预览图标打开商品面板。历史任务在「历史对话」中切换，完整报告和热度榜在「研究结果」中查看。

取得商品后，对话上方常驻「查看采集结果」，无需等待AI分析完成。面板分别展示全部候选、当前Hot榜和研究报告，支持按标题、文案、商品ID搜索，按想要数或标价排序及分页。点击商品查看已采集的完整详情或搜索展示文案，并可打开闲鱼原商品；未取得完整详情时明确标注。分析失败或任务暂停后仍可浏览已有商品。对话发送「查看采集结果」「查看采集商品」「查看热度榜」也会打开同一面板。

对话采用用户消息与助手正文的形式，只显示简短处理状态、结果和必要确认。工具事件仍保存供后台排查，日常页面不展示执行过程或JSON。对话刷新后恢复。预览采用手机商品详情结构，包含卖家、价格、标题、分段详情、图片/视频和买家底栏；实际客户端渲染仍以闲鱼为准。

对话顶部直接选择「发布账号」，显示昵称和账号ID；点旁边的刷新图标可读取新添加的账号。只有一个已登录且启用的账号时自动选取，多个账号时保留待选择状态或使用明确保存的默认选择。新任务保存本次账号，后续修改默认账号不会改变已有任务。审核模式可先研究再选账号；自动模式创建任务前要求确定目标账号。预览底部和发布确认单再次展示目标账号，商品发布后的AI回复、发货关联使用同一账号。任务执行中或已有发布结果时锁定选择；切换目标会撤销旧发布快照并重新计算确认指纹，失败重试的发布日志也同步新账号。

生成后在预览底部点「同步发布」，勾选其他账号，共用当前预览版本的标题、完整详情、价格和素材。提交前逐个展示账号所在地、AI模型、交付卡券和缺项；统一确认后，每个账号进入独立的持久发布任务。对话内的「各账号发布结果」分别展示商品链接和失败原因，刷新后继续查询。再次选择已发布、执行中或结果待核对的账号会复用原记录；失败账号单独重试，已发布但托管配置未完成的账号可只重试托管。同步任务归在原商品下，不重复出现在历史对话中。原商品已发布后也可以继续同步到新账号。

「分类与托管设置」「默认经营设置」和同步发布确认页均提供AI接口选择。已有账号的回复配置、AI铺货配置与新保存的共享接口都可复用；密钥仅在服务端按用户归属解析，选项只返回配置名和模型名。新增接口支持OpenAI兼容、Anthropic和Gemini，可拉取模型列表后选择，也可手填。保存共享接口不会立刻改动任何账号的开关；在商品发布成功并启用托管时应用到目标账号。选择的配置参与发布指纹校验，模型接口修改后旧确认失效。默认设置所选的共享接口也用于之后新任务的文案生成。

默认「审核后发布」：完成商品包后停止，用户切换文案版本、检查标题/详情/价格/图片/视频和待确认信息，再点击「检查并发布到闲鱼」，勾选确认单中的商品内容、AI回复和自动发货，最后确认发布。按钮提交当前预览指纹，服务端重新计算；内容变化会拒绝旧指纹，要求重新检查。通过审核的发布内容保存为快照。

显式选择「自动生成并发布」后，新任务或下一轮生成在条件齐备时直接发布。已完成任务切换模式只改变后续生成行为，当前草稿仍可点击发布。只有一个可用账号时自动选取；平台分类按商品内容调用原项目的闲鱼推荐接口自动匹配。分类及属性、所在地、发货卡券或专属网盘内容都在当前页调整。标题、分段长详情和售价可在预览顶部直接编辑，也可以对话要求扩写。缺项会停在预览并显示原因。

发布复用原项目 `execute_single_publish`，使用固定的 `ops:TASK_ID` 请求号及持久发布日志。成功请求复用商品链接；平台结果未知时暂停重试，需在原后台发布日志核对。明确失败可按当前预览重试。普通卖家接口只上架图片，鱼小铺可上架视频，预览中会提示这一限制。地址库选项在预览时只读选定并随快照冻结，预览操作不消耗地址使用次数。

鱼小铺发布前的媒体上传或表单校验失败属于明确失败，不锁为“发布结果未知”；最终商品发布接口调用后发生网络异常时继续保留对账保护。OSS视频分片使用平台提供的签名地址，保持原始URL编码并省略HTTP库自动添加的Content-Type，避免签名不匹配。上传日志仅保存状态和错误码，排除含签名的完整地址。上述共享发布器修复随本地operations部署挂载，也包含在其镜像构建中。

发布成功后复用原项目的AI回复与卡券服务：将商品事实和FAQ写入该商品的AI提示，添加商品与卡券的关联，并在发布成功后启用所选卡券、账号AI回复和自动确认发货。优先沿用已有AI模型；交付内容可匹配唯一同类卡券、手动选择已有卡券，或自动创建商品专属文本卡券。账号开关的影响范围在审核单中明示。托管配置失败保留已发布结果，可单独重试配置，不重复上架。

### 在对话中管理发货卡券

商品对话顶部「发货卡券」和预览底部「选择 / 新建」打开同一面板，可以搜索、翻页选择已有卡券，查看固定文字发货内容，或填写名称与完整交付内容创建文字卡券。已有文字、批量卡密、图片、API类型均可选择；API凭证和批量卡密内容不会返回选择列表。新卡券写入原项目卡券表，在原卡券管理中也能看到，先以未启用状态保存。创建请求重复提交复用同一卡券。

也可直接发送上述卡券指令，名称相同或搜索匹配多张时提示指定ID。新建时缺名称或内容会保留输入，下一条补充「发货内容：…」或「名称：…」即可，也可打开面板补齐。「取消新建卡券」取消这次未完成的输入。卡券命令独立执行，发货链接不会被当作商品素材目录或交给普通问答模型。创建卡券需要先打开对应商品任务。

卡券选择按当前任务保存，切换卡券会清除旧的专属交付文本和发布确认；研究过程中也可选择。自动发布前读取最新选择，并在冻结快照时检查版本，避免并发修改被旧参数覆盖。原有自动匹配仅在唯一同类卡券时触发，单张无关卡券不再自动套用。同步发布的各账号沿用当前商品的卡券。

已发布商品支持在同一面板换绑：先保存选择，查看线上卡券与新内容，勾选确认后替换并启用。替换仅影响本件商品的关联，保留其他商品关系和原发布记录；不会再次上架。它也更新原发布快照中的发货配置，后续托管恢复使用新卡券。发布提交中或结果待核对时锁定修改。审核模式在发布确认单确认发货；显式自动发布模式使用已经选定的卡券在发布成功后绑定。

实际热度字段缺失的商品单列，明确的零保留为零。榜单只描述本次采样；竞品真实销量未验证。价格使用同类有效样本中位数及已配置的成本/售价边界。

明确说「Hot10」「Top20」或「前5件」时，数量会保存到任务中。Hot10 默认最多采集30件候选、补全10件详情，并将AI竞品分析限制在10件以内；候选数量和最终热度榜分别展示。采集到最后一页时也遵守候选数量上限。断点继续会复用当前研究范围内已完成的分析，其他历史证据保留。模型因输出长度上限截断JSON时增加输出额度后重试，并明确区分截断、响应超时、限流和HTTP错误。

## 用对话完成商品运营

`operations/dialogue.py` 提供实际操作工具清单。明确的常用指令直接执行，其他自然语言由现有文字模型生成至多8步的结构化计划，再通过校验调用原有服务。每一步保存结果与隐藏的工具事件，前台只展示完成结果或缺项；操作失败保留已完成步骤。所有查询和写入均按登录用户及任务归属处理；工具清单不包含任意脚本或终端执行。

可直接说：查看账号、用「昵称」发布、所在地设为杭州、切换审核模式/自动模式、售价改成29.9、自动定价、用第2版、扩写详情、添加视频、删除第1个视频、添加图片、用第2张图片做封面、查看分类、查看卡券、复用「AI配置名」、拉取模型、使用模型「模型ID」、停止、继续、查看研究报告、历史任务、打开「任务名」、导出商品包。也支持一次说多项要求，例如「用第二版，售价改成29.9，加上素材里的视频，然后给我发布确认单」。同一商品的生成、封面和排期可以连续交代，系统保存步骤并在生成完成后继续。批量排期作为独立操作提交。

新增AI接口可直接发送「新增AI接口，名称：通用客服；地址：https://接口地址/v1；API Key：密钥；模型：模型ID」。也可分条发送「新增AI接口」「接口地址：…」「API Key：…」；缺项会保留进度并提示补充。省略模型会先保存待选接口并拉取模型，再回复「使用模型『模型ID』」。密钥在本地解析后交给原接口服务，聊天记录隐藏密钥，模型规划上下文排除标记为私有的卡券交付信息。

「发布当前商品」返回账号、售价、分类、所在地、图片/视频数量、AI回复与卡券确认单；回复「确认发布」才提交。同步发布可说「同步发布到『账号A、账号B』」或「同步发布到所有可用账号」，然后回复「确认同步发布」。已发布商品绑定新卡券后，会先展示交付内容，再回复「确认换绑卡券」。确认单持久保存、30分钟有效、执行时消费且重新校验当前内容指纹；修改内容后旧确认失效。显式开启自动模式的任务仍沿用既有生成后自动发布规则。

自动定价优先使用有效同类标价中位数。样本少时给出明确标注的试售价：优先使用少量同类标价，再使用关键词相关的软件/其他商品标价，排除代做服务、订金和低价引流；仍无有效标价时使用已配成本或边界、商品类型的试售起点。全部建议遵守成本与售价边界，保留样本ID和依据；相关商品不冒充同类销量证据。审核模式下在预览与发布确认单中检查。价格不足或草稿漏存的旧任务可直接说「准备发布草稿」，补齐并保存，不重跑研究和文案。

添加视频/图片默认读取当前素材目录，也可在指令中附具体文件完整路径。增删媒体、设置封面直接更新当前任务及素材库草稿，保留文案、定价、卡券和研究。视频上限与原项目一致：3个，每个100MB；图片最多9张，每张20MB。视频以分块方式计算摘要，避免整段读入内存。发布效果仍取决于账号平台能力：鱼小铺可带视频，普通卖家接口只发布图片。

## 运行与恢复

### 批量定时发布

在商品运营对话内给出商品关键词、每个素材文件夹的完整路径、对应发布时间和发布账号。例如：「仍然卖AI口播源码，账号用店铺A，/Users/用户名/Desktop/素材/第一天 明天20:00发布，/Users/用户名/Desktop/素材/第二天 后天09:30发布，先生成给我审核。」自动模式可明确说「按这些时间自动发布」。每个文件夹生成独立商品，相同商品可以复用当前研究，文案、事实、定价和素材独立生成。单批支持1至50个文件夹。

原始时间表达交由服务端按 Asia/Shanghai 解析，包括明确日期、今天/明天/后天、下周一及24小时制时间；界面与确认单均标注北京时间。排期先逐项校验路径、日期和账号，再用一个事务建立全部任务，重复请求复用同一批次。各商品立即进入准备队列，到发布时间才调用平台发布器。到期发布优先于普通生成任务，运行中的生成任务结束后再领取到期商品。

审核模式先准备所有商品，对话中说「审核整批排期」，逐件查看预览及AI回复、卡券设置，再说「确认全部排期」；也可以打开单件商品按既有流程确认发布。整批审批会重新检查每件商品并在单个事务中提交；任一商品变化时整批确认失效。自动模式在草稿和发布条件齐备后自动进入定时等待。改文案、价格、卡券或发布设置会撤销该商品原定时批准，保留排期时间并等待重新检查。

对话支持「查看排期」「把任务『ID』的发布时间改成明天21:00」「取消排期『ID』」。页面显示可滚动的批量排期区域，包含每件商品时间、账号、状态及预览入口。取消排期保留草稿并切回审核模式；「停止」暂停当前任务，原排期保留。排期持久保存在 `xy_operation_schedules`，不依赖浏览器页面保持打开。

请保持电脑唤醒、Docker服务运行、素材可读及账号登录。定时表示到点提交，平台处理仍需要时间。服务短暂中断后30分钟内恢复会继续到期任务；超过30分钟则标记「已错过排期」，保留商品，重新设置时间后再发布。测试替换平台发布调用，验证无提前发布、重启恢复、错过时间保护、归属隔离、批次审批、改期和取消。

前端源码接入 `frontend/src/pages/operations/ProductOperations.tsx`，复用原后台菜单、路由、请求封装和素材库。旧 `/api/v1/operations/console` 地址自动转到原后台 `/product-operations`。

仓库内提供可复用的 `operations/compose.yaml`。重新部署时先在 `frontend` 目录按现有锁文件安装依赖并执行 `npm run build`，再从仓库根目录将该配置追加到现有 Compose 配置后，例如 `docker compose -f docker-compose.yml -f compose.local.yaml -f operations/compose.yaml up -d --build operations frontend`。桌面和文档根目录默认使用当前 Mac 用户目录，可通过 `OPERATIONS_DESKTOP_ROOT`、`OPERATIONS_DOCUMENTS_ROOT` 调整。

服务由项目的 `compose.local.yaml` 注册；使用和主项目相同的启动命令。任务保存在 MySQL 的 `xy_operation_jobs` 中。任务租约过期后，工作进程会从已保存的页、详情、模型分析批次恢复。每次模型调用和平台请求都有时限，并限制单任务采集规模。

竞品分析默认每批2件，控制输入节选和模型输出长度。单次HTTP请求90秒、每次分析100秒，由研究层统一管理重试；超时或返回不完整JSON时缩小批次再试一次。成功批次逐批保存实际样本ID，继续时跳过已完成的样本，也兼容旧的10件分析批次。后续接口持续超时时，提示具体失败环节与已保存进度。

任务执行时，输入框旁显示「停止任务」。停止会撤销任务租约，工作进程每秒检查状态并中断正在等待的模型或采集请求，已完成的检查点保留；点击「从断点继续」恢复。已提交的平台发布通过发布记录保护，发布结果待核对时先核对实际商品。停止本地请求后，第三方接口服务端的计算是否终止取决于接口实现。

素材目录为只读挂载，默认开放桌面与文档中的具体子目录；只有管理员可提交本地路径。跳过密钥、隐藏目录、依赖和真实环境配置；模型仅接收文档摘要/OCR文字及对应素材索引。源码未执行。

图片 OCR 使用 Tesseract 中文/英文，PDF 使用 pypdf，Word 直接提取 docx XML。扫描 PDF 尚需提供可读说明或图片；图片 OCR 的文字属于材料描述。最多3个、每个不超过100MB的视频复制为商品展示素材，并随草稿保存；视频内容不作为功能证明。源码文件只登记清单。

商品草稿使用已有 `ProductMaterialService` 入库。同一任务备注用于恢复时查找已有素材，避免重复入库。

## 经营反馈与商品优化

对话支持「刷新近7天经营数据」「查看近30天经营表现」「查看全部账号经营数据」「优化当前商品」「查看优化记录」「确认应用优化」「核对优化结果」。顶部经营反馈图标打开同一份结果，包含店铺概览、本地订单/咨询、单件商品计数、观察建议、优化版本和完整前后文案对比。查看快照只读本地；刷新才读取平台。多账号汇总分别展示最多10个账号的已保存快照和本地记录，刷新可指定账号。

店铺概览复用原数据罗盘接口，支持近1/7/30天的曝光、访问、咨询、支付和退款字段。商品浏览与想要取自该账号已同步或已发布商品的详情，累计计数有独立采样时间；一次刷新读取最新3件，也可通过对话指定商品ID刷新。目录最多展示100件。快照持久保存到 `xy_operation_metric_snapshots`。有至少相应天数前的基线时，显示两次采样之差及实际起止时间；计数回退、缺字段或缺基线时增量留空。店铺总量始终与单品分开，缺失数据不填成零，也不冒充销量归因。

本地订单按下单时间和当前状态统计，按账号、订单号取最新记录，排除待付款及模糊的pending状态；仅已确认付款状态计入付款笔数和已知人民币金额。退款是该下单区间订单的当前退款状态，并非期间退款流水。咨询按商品去重会话，排除自身/系统消息、重复消息及自动发货触发，回复与发货异常另计。本地记录覆盖受订单同步和消息日志影响，零条不代表平台零笔。买家信息、聊天正文、交付私密内容和凭据不进入报告或优化模型。

优化基于现有商品事实、研究和可核对反馈生成标题与完整详情，当前版本保留售价。审核模式先生成30分钟有效确认单，再对话确认或在前后对比中勾选应用。自动发布模式下仍先给方案；另明确说「自动优化并应用当前商品」才直接应用这次修改。优化草稿会校验内容和账号/经营参数，修改已确认排期的草稿会撤销旧排期批准。

已上架商品复用原项目鱼小铺编辑服务，保留商品ID、分类、图片、视频、规格、库存和运费，在构造提交前重新校验平台表单指纹。平台暂未提供编辑表单时保留方案并显示原因，线上内容保持原状。成功后同步本地商品描述及已经启用的该商品AI回复知识，卡券绑定保持原设置。结果未知时持久标记、暂停重复编辑，通过「核对优化结果」读取平台比对；历史保存在 `xy_operation_optimizations`。所有测试使用隔离用户及模拟接口，不提交真实上架或修改。

## 验证

先停止 operations 工作者，再通过同一 Compose 配置执行 `run --rm -T --no-deps operations python -m unittest discover -s operations/tests -v`，结束后重新启动 operations。

发布测试替换平台调用，检查默认审核、自动分支、预览快照、归属隔离、成功复用及未知结果防重。测试使用隔离的账号和商品夹具，验证分类推荐、默认联动、卡券归属、绑定幂等和配置失败恢复。浏览器使用拦截请求验证发布确认和预览过期拦截；测试不创建真实商品。商品结构与三版长详情分开生成；已完成版本保存到检查点，重试只补缺少的版本。长详情使用独立的响应时限，单次请求最多230秒、生成步骤总时限300秒，超时保留已有素材和研究。

## 商品工作台、经营模板与素材工坊

原商品运营页顶部和会话侧栏均可打开「商品工作台」。对话也能直接调用相同功能，执行结果保存在当前会话。

- 「查看商品总控台」「查看待处理商品」「找出未绑定发货的商品」「找出未配置AI的商品」：按账号、商品状态和配置缺项查询，可搜索标题或商品ID，分页查看。商品来自本地运营任务和已同步目录，重复发布记录按账号及商品ID归并。已同步表示本地存在记录，线上在售状态以闲鱼为准；回复和发货标签表示当前配置检查结果，账号登录状态仍需保持正常。
- 已同步但尚无运营会话的商品，点击「打开运营」会接入原商品ID的会话，后续可使用卡券绑定和线上优化。此操作仅创建本地会话。
- 「保存经营模板『口播源码』」「查看经营模板」「应用经营模板『口播源码』」「更新经营模板『口播源码』」：复用成本/成交底线、商品类型、确认事实、文案要求、AI接口引用及卡券选择。模板排除目标账号、素材路径、私有交付文字、实际凭据和发布授权。同名模板有变化时需明确更新；应用时重新校验模板版本及卡券/接口归属。应用会替换模板覆盖范围内的经营规则，包括清除模板中未设置的旧成本边界；素材、目标账号及各商品的私有交付文字仍由该商品单独确定。更换卡券选择时移除旧私有交付文字，避免发货来源冲突。
- 新商品可以说「应用经营模板『口播源码』，然后读取 /Users/用户名/Desktop/素材目录」。修改现有草稿的事实、类型或文案要求时，会保留研究及素材重新生成并等待审核。原定时发布批准及旧发布确认随内容修改失效。
- 「打开素材工坊」「生成三套封面」「使用第2套封面」「图片排序为3、1、2」：用现有图片、当前商品标题和已提取的商品事实，合成商务深蓝、简洁留白、明亮醒目三种配色的1200×1200 JPEG封面。可指定标题与最多3条事实；过滤下载链接、提取码等私密交付信息。当前为本地文字与图片排版合成，所用图片和事实来自当前商品。
- 生成只保存候选，选择后才加入发布预览；可点击封面打开大图。切换候选会替换上一张生成封面，同时保留原图和视频；已有9张原图时先腾出位置。排序要求每张图片序号出现一次，首张为封面。发布中的任务和已发布商品的素材调整通过现有平台编辑流程处理。

模板表为 `xy_operation_business_templates`，启动时自动创建。API新增 `GET /products`、`POST /products/open`、`GET/POST /business-templates`、`POST /business-templates/{id}/apply`、`POST /jobs/{id}/workshop/covers`、`PUT /jobs/{id}/workshop/cover`、`PUT /jobs/{id}/workshop/order`。均复用原登录与归属检查，模板/图片变更同步素材库，并清除过期发布确认。字体优先使用镜像已安装的文泉驿中文字体，也支持通过 `OPERATIONS_CJK_FONT` 指定。

## 整条指令自动续办与批量审核

一条指令可以按顺序包含模板、研究/素材生成、文案修改、封面候选/选用和排期。例如：「应用经营模板『口播源码』，读取 /Users/用户名/Desktop/素材，生成三套封面，使用第2套，明晚8点发布」。解析成多个步骤后存入 `xy_operation_workflows`，生成步骤完成后自动继续。任务卡默认只展示完成数和当前结果，展开可看简明待办。对话支持「查看整条任务」「暂停整条任务」「继续整条任务」「取消剩余步骤」，原「停止任务」按钮也会暂停整条任务及正在生成的商品。

连续准备期间用 `workflow_hold` 阻止提前发布和同步发布。自动模式在所有后续准备完成后重新检查，并使用最终的封面、价格、账号与排期；审核模式完成后等待审核。指定“发布确认单”为最后一步时仍等待确认。相对发布时间在接收整条指令时转换为北京时间对应的固定时间，跨天生成后沿用原日期；已过期时间会显示待处理。新对话套用模板后沿用模板保存的研究关键词，读取素材会创建真正的商品任务，后续步骤跟随这个商品。

任务及当前步骤持久保存，等待生成时重启服务会继续检查。模型或采集失败时保留后续步骤，修正后可继续；卖家手动修改当前商品会暂停后续操作并要求核对，避免覆盖。某一步执行过程中服务突然中断时，先提示核对这一步已有结果，再由卖家继续；生成等待阶段可自动恢复。暂停会撤销生成租约并中断正在等待的后续调用；取消剩余步骤会清除关联商品的执行占位，保留内容并切回审核模式。

批量审核入口在商品运营顶部日历内的「批量审核」、排期卡片「审核整批商品和排期」以及对话「打开批量商品审核台」。可选择已有批次，集中查看每件商品的所有图片、展示视频、完整详情、价格、账号、分类、所在地、发布时间、AI回复与卡券选择。未就绪商品显示具体原因并保留预览。仅选择就绪商品，取消勾选即可跳过；标题、详情与价格可在审核台内修改，保存会携带内容版本指纹防止覆盖新修改，并重新生成审核单。已经跳过的选择在修改和刷新后保留。

勾选发布与托管确认后，只提交所选商品。服务逐件重新检查账号、卡券与内容，在一个事务内批准所有选中项；任何选中商品已变化时整次审批回滚。审核单30分钟有效，成功后相同选择重复提交复用结果。未选商品保留原状态，审批成功仅进入定时等待，到点后由原发布队列提交。当前批量审核面向已建立的排期批次，一批最多50件。

批量审核刷新保留预览与全部选择，读取失败保留原内容；已选商品变化、被移出批次或排期过期会明确提示并撤销确认。页脚可按账号核对完整商品、售价、北京时间及托管清单。提交报错后须刷新核对实际结果，成功后清空本次选择；未保存编辑有导航与浏览器刷新提醒。详见 [连续任务与批量审核](../docs/连续任务与批量审核.md)。

批量审核可直接打开当前商品的「分类与托管」和「发货卡券」，按审核行的任务 ID 独立读取最新内容，调整账号、分类、所在地、AI 接口、托管开关或选择／新建卡券。保存或取消后沿用原批次、筛选、选择及预览状态，重新读取审核单；账号变化导致商品被筛选隐藏时，可一键定位该商品。设置读取失败与返回审核读取失败分别重试，已接受的保存不受背景对话刷新失败影响。

审核台支持按标题、素材文件夹、任务ID和账号搜索，并按账号、就绪、待处理、已提交和已选择筛选。筛选保留原有选择，“选择筛选内就绪商品”和“取消筛选内选择”只影响当前显示范围；底部显示总选择、账号数及筛选外已选数量，可展开核对最终提交清单。“查看全部已选”会清除其他筛选，方便逐件确认。刷新时沿用先前选择，审核成功后清空已选范围，避免把剩余商品自动加入下一次提交。

预览支持上一件/下一件、点击图片查看大图，以及放大模式；放大模式收起列表、筛选和提交区，检查完成后点击“返回审核”。手机列表采用纵向展开，选择商品后自动收起。文案或价格有未保存修改时，切换商品、批次、刷新、关闭或跳到其他功能前会显示处理选项：保存后继续、放弃修改并继续、留在编辑。保存冲突保留编辑内容，旧版本指纹校验继续生效。审核单过期会禁用确认，需要刷新重新检查。

新增 API：`GET /jobs/{id}/workflows`、`POST /workflows/{id}/control`、`GET /schedule-batches`、`POST /schedule-batches/{id}/review`、`POST /batch-reviews/{id}/approve`。审核单保存在 `xy_operation_batch_reviews`；内部发布快照保留在服务端。批量预览向当前所属用户返回卡券名称、开关和交付预览，固定文字显示全文，卡密和 API 凭据不返回。服务健康检查包含商品、恢复与连续任务三个工作者。

### 上架验收与付款后交付预览

新商品成功上架并尝试关联托管后，恢复工作者自动验收原发布记录中的确切商品 ID。发布进度里展示标题、完整详情、售价、图片／视频数量、AI 回复知识与模型开关、发货卡券版本与账号开关的核对结果。状态分为一致、有差异、待核对、本次跳过。平台字段缺失或读取超时保留为待核对，商品上架成功状态保持不变。历史商品可在发布进度点击「重新验收」，或对话发送「上架验收」「核对上架内容」。

验收复用当前鱼小铺商品详情读取接口，普通卖家及平台暂未返回的字段会显示待核对；媒体只核对数量，实际内容与封面顺序仍需查看线上商品。AI／发货核对的是配置关联，实际回复与订单交付请查看原记录。重复请求合并，切换账号时忽略旧响应。验收只读，不提交发布、不修改售价、不发送消息或分配卡密。

发布总览、批量审核和多账号新建审核增加「付款后买家收到的内容」，单独标明仅卖家审核。固定文字卡券与专属网盘交付显示完整文字，长内容可滚动；批量卡密、API 与图片卡券显示交付方式，不消耗库存或调用取货接口。售前详情出现同一个交付链接时提示核对公开范围。交付预览随审核快照参与校验，卡券变化后需重新审核。已发布商品确认更换卡券后重新触发验收，并以最新确认的交付设置为基准。

接口：`GET /jobs/{id}/publication/audit` 只读取保存报告；`POST /jobs/{id}/publication/audit` 执行只读验收。均校验当前用户对任务的归属。详见 [上架验收与交付预览](../docs/上架验收与交付预览.md)。

验收有差异、部分字段待核对接入运营待办（`kind=audit|audit_pending`）；托管未完成优先展示，单件商品只计一次。列表仅投影字段名称与状态，完整审核值在报告内查看。点击「查看验收报告」后返回保留账号、批次、筛选、页码及列表位置，并刷新实际结果。重验中保留既有待办，验收一致后移除；分页缩短自动回到有效页。刷新失败保留旧列表与选择并暂停处理，单独重读恢复。对话支持「查看上架差异」「查看验收待核对」「查看托管待办」。

验收报告增加「配置 AI 回复」「检查发货卡券」，从原成功发布账号和商品 ID 独立读取配置，处理完回到原报告。回复支持复用／新建接口及拉取模型，先看当前与确认后的模型、开关和商品知识，再勾选应用；账号模型和开关影响该账号其他商品，自定义提示与交付配置保留。`GET/POST /jobs/{id}/publication/reply` 校验 owner、成功日志、版本指纹，并合并重复确认。发货沿用选择／新建、保存选择、核对并确认换绑流程；卡券已绑定但开关关闭也可确认修复，账号禁止发货范围保持生效。本地关联全部满足审核要求才标记托管完成，仍有缺项保留待办；验收报告继续独立只读。

验收报告新增「账号检查」，对话支持「检查当前商品账号」「查看发货规则」。按原成功发布记录检查本地登录配置、回复与发货开关，提供带账号筛选的管理链接。逐条展示条件发货规则与关单行为；审核确认后仅向所选规则追加当前商品 ID，保持其他商品和账号开关。确认绑定及交付版本后才允许调整，使用 owner 校验、规则与卡券指纹、事务和幂等回执。验收与发货卡券提示改为读取实际规则，不再用旧兼容标记将条件限制误判成所有订单禁止发货。接口：`GET /jobs/{id}/publication/account`、`POST /jobs/{id}/publication/account/rules`。具体流程见 [上架验收与交付预览](../docs/上架验收与交付预览.md)。

### 商品版本记录与回退

商品对话顶部和批量审核台增加版本入口；生成草稿、修改文案/价格/图片/视频时自动留档，可命名保存、查看差异并恢复。支持「查看商品版本」「保存当前版本『首轮通过』」「恢复上一版本」「确认恢复版本」。恢复只作用于未发布的本地草稿，沿用当前经营设置并重新进入审核，定时发布须再次确认。详情见 [商品版本记录与回退](../docs/商品版本记录与回退.md)。

### 商品发布前检查

商品运营页、预览和批量审核台增加「商品检查」，对话支持「检查当前商品」「按检查建议优化文案」「确认应用优化」。结果区分发布缺项与内容建议，覆盖文案完整度、事实编号、媒体文件、封面尺寸、成本与托管配置；使用当前所选文案版本。优化先生成审核对比，通过后再应用，售价和卡券保留。详情见 [商品发布前检查](../docs/商品发布前检查.md)。

### 发布日历与批量改期

顶部日历汇总各账号每天的排期，支持7/14/31天及账号、批次、状态筛选；同账号同一分钟或间隔不足5分钟显示建议。可勾选商品整体顺延、提前或按间隔错开，先看新旧时间再确认；所选商品在一个事务内调整，撤销旧发布批准并切回审核模式，内容与卡券保留。对话支持「查看发布日历」「查看时间冲突」「整批排期顺延一天」「这批商品从明天20:00开始，每隔10分钟发布」「确认调整排期」。详情见 [发布日历与批量改期](../docs/发布日历与批量改期.md)。

### 运营待办与准备重试

顶部、侧栏及日历中的「运营待办」集中查看准备中断、发布失败、发布条件缺项、历史错过排期、结果待核对和已上架托管待完善。支持账号/类型/批次筛选、分页、逐件检查与带入原日期改期；结果核对与托管重试均使用明确的对应任务ID。选择商品后先生成准备重试单，再确认进入原准备队列，撤销旧发布批准、切回审核模式，研究素材与卡券保留。对话支持「查看运营待办」「查看错过的排期」「重新准备当前商品」「重新准备本批次商品」「确认重新准备」。详情见 [运营待办与准备重试](../docs/运营待办与准备重试.md)。

### 会话草稿与对话查找

各会话及新建对话分别保留草稿，侧栏显示草稿标记，普通内容在当前标签页刷新后恢复，按登录用户隔离。含密钥标记、交付信息或链接的内容仅保存在页面内存。发送失败保护后来输入的新草稿，面板快捷命令也保留未发送文字。会话顶部的放大镜或 Ctrl/⌘+F 可查找当前已加载的可见消息，支持高亮、上下定位和 Enter/Shift+Enter。详情见 [会话草稿与对话查找](../docs/会话草稿与对话查找.md)。
